# 使用指南

这份文档说明：在 Slack 里跟当前这个助手说话时，它能做什么，以及你怎么下指令。

当前绑定的仓库是 [hejianghu/coach](https://github.com/hejianghu/coach)，默认分支是 `main`。这个仓库是公开的。

## 我是谁

你在这条 Slack 线程里发消息，唤起的是 Cursor Cloud Agent。我在一台远程 Linux 环境里读仓库、改文件、跑命令，做完回到同一条线程里回复。

你等待的时候，线程下面通常只有一行状态。结果会写在线程消息里。

这里改的是 GitHub 上的这个仓库。你电脑上的文件夹不会自动跟上。要在本机看到改动，拉取对应分支。

## 直接能做的事

### 按这个仓库教你学

这是仓库的本职，规则在 `SKILL.md`。

你说想学什么，我来提问、讲解、测验。一个模块的掌握度到 80% 再进入下一个。进度写在 `_learning/<主题>/profile.md` 和对应的模块文件里。换一条新的 Slack 线程之后，只要这些文件还在仓库里，说「继续学某个主题」就能接着来。

可以说的话：

- 「我想学 X，从零开始。」
- 「继续学 X。先复习再往下。」
- 「停在这里。」我会把当前进度写入 `profile.md`。

`config.json` 里的 `notesDirectory` 现在是空的。这台环境也访问不到你电脑上的笔记目录。要另存笔记，告诉我写到这个仓库里的哪个路径。

仓库是公开的。学习笔记一旦提交并合并，GitHub 上谁都能看到。要留在本地、不进 GitHub，就明确说「不要提交进度」。那种文件只存在于当次环境，下次新任务读不到。

### 改这个仓库

我可以读文件、改文件、跑命令、看提交历史。

代码改动走这个流程：

1. 从 `main` 拉出分支，分支名以 `cursor/` 开头，并带这次任务的固定后缀。
2. 提交并推送到 GitHub。
3. 对 `main` 开一个草稿 Pull Request。
4. 在线程里给你 PR 链接。

合并由你来做。我不会自己把分支合并进 `main`。

### 查这个仓库的 GitHub 信息

可以看 Pull Request、CI 结果和提交记录，并用中文讲给你听。

用 GitHub 命令行时只能读。建 Issue、改仓库设置不走那条通道。开 Pull Request 用的是另一条专用通道，这是我能做的写操作。

### 查公开资料

可以搜索网页、打开公开链接，核对之后再回复你，或写进仓库。

### 处理已连接的 Gmail

当前环境已经接上 Gmail。你可以让我搜索、阅读、起草。

搜索和阅读可以直接说。起草是默认动作：我先把草稿放进邮箱，你自己看过再发。

发出、转发、丢进垃圾箱、删除，都要你在消息里写明要做的动作和对象。没写明，我只做到草稿或列表。

邮箱地址不会写进这个仓库。

### 使用 Slack

默认只在当前线程回复。

可以读这个 bot 已经加入的频道里的近期消息。你点名频道，并明确说「发到那里」，我可以代发，前提是 bot 已经在那个频道里。bot 不在的私人频道，我读不到，也发不进去。

### 等一个后续事件再继续

你可以让我盯着一件事，先停住，事件发生后再接着做。例如：

- 某个 Pull Request 有了新评论
- 某条分支的 CI 全部跑完
- 某个 Slack 频道或线程里出现新消息
- 过一段时间再回来做一件你写明的事

盯的时候我会说明在等什么，然后结束这一轮。事件到了，同一条对话会继续。

### 在浏览器里验收网页

任务如果是改一个能打开的网页应用，我会自己点主要流程做验收。当前这个仓库没有网页，这条用不上，除非你给我一个公开页面让我核对。

## 做不到的事

- 访问你的 Windows 电脑。本机目录、本机 Cursor、本机笔记软件，这里都碰不到。
- 改别的仓库。这条对话绑的是 `hejianghu/coach`。要改别的项目，直接说仓库地址。我会请你切换仓库；换过去是另一次任务。
- 目标没说清就扩大范围。我会停下来问。你没回复时，我按问题里写明的假设继续，并在结果里说明假设了什么。
- 自己合并 Pull Request。

## 怎么下指令

一条消息里写上你已经知道的这些：要的结果、动哪些文件或完全别改代码、不要做什么、怎样算做完。

适合直接说：

- 「我想学维特根斯坦的图像论，从零开始。进度可以提交。」
- 「继续学图像论。先复习再往下。进度不要提交。」
- 「只改 README 的 Quick Start，补三行 Slack 用法。别动别的文件。」
- 「用中文说明 `main` 上最近一次提交改了什么。」
- 「搜我邮箱里最近 7 天主题含 invoice 的信，只列发件人、时间和标题。」
- 「这个需求不在 coach，仓库是 `<仓库地址>`，请切换。」

先问再做的情况：

- 只说「看看」「优化一下」，没说看什么、改完要达成什么。
- 同一条消息里又要上课又要改很多文件，没说先后。
- 说「按你觉得好的重做一版」，范围是开着的。

## 一次任务怎么结束

教学和问答：结果在这条线程里。需要保存进度时，才写 `_learning/`。

改代码：线程里会有草稿 PR 链接，以及改了哪些文件、你要看的点。PR 保持草稿，等你看过再标记成可以评审或自己合并。

你在我进行中又发了一条消息，我会把它当作对当前任务的补充。范围变了就直接说「停下」或「改成只做某一件事」。
